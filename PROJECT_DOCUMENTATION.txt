================================================================================
RECRUITING OPS CENTRE — COMPREHENSIVE PROJECT DOCUMENTATION
================================================================================
One-stop shop for restaurant employee management: recruiting pipeline,
interview assessments, employee records, paystubs, and documents.

GitHub:  https://github.com/abhinavmanocha/recruiting-ops
Local:   http://localhost:5001
Login:   admin / recruitops (configurable via RECRUIT_USER / RECRUIT_PASS env vars)

================================================================================
1. PURPOSE
================================================================================

The Recruiting Ops Centre consolidates the full employee lifecycle into a
single internal web application. It replaces paper forms, scattered
spreadsheets, and the legacy standalone paystub viewer with one cohesive
tool. The owner/manager can:

  - Post jobs and track applicants through a hiring pipeline
  - Conduct structured interviews using the official SLF assessment form
  - Store permanent employee records (SIN, wage, certifications, etc.)
  - Keep paystub PDFs and documents organized per employee
  - Access everything from anywhere (Cloud Run / Armbian / Cloudflare tunnel)

================================================================================
2. ARCHITECTURE & TECH STACK
================================================================================

MAJOR:
  - Backend:  Python Flask (single app.py, ~850 lines)
  - Frontend: Single-page HTML/JS (templates/index.html, ~2100 lines)
              No build step, no framework — vanilla JS + custom CSS
  - Storage:  File-system JSON (no database required)
              data/jobs/      -> job postings
              data/candidates/-> applicants
              data/interviews/-> scheduled interviews + assessment forms
              data/employees/ -> hired staff (employee.json + paystubs/ + documents/)
  - Auth:     HTTP Basic Auth on all routes (before_request hook)

MINOR:
  - Resume parsing: PyMuPDF (PDF text) + python-docx (DOCX) + regex engine
  - Optional Gemini API enhancement for resume parsing (uses localStorage key)
  - Drag-and-drop kanban via SortableJS (CDN)
  - Resume files saved to uploads/ (or /tmp/uploads on Cloud Run)
  - Dockerfile + gunicorn for Cloud Run deployment
  - import_employees.py: legacy paystub system -> employee database migrator

4. API REFERENCE (all routes require HTTP Basic Auth)
================================================================================

JOBS
  GET    /api/jobs                         list (with counts per stage)
  POST   /api/jobs                         create
  GET    /api/jobs/<id>                    detail (with candidates + interviews)
  PUT    /api/jobs/<id>                    update
  DELETE /api/jobs/<id>                    delete (+ linked candidates)

CANDIDATES
  GET    /api/candidates                   list (?job_id=, ?stage=, ?search=)
  POST   /api/candidates                   create
  GET    /api/candidates/<id>              detail (with interviews + criteria)
  PUT    /api/candidates/<id>              update
  PUT    /api/candidates/<id>/stage        quick stage change (kanban)
  DELETE /api/candidates/<id>              delete (+ interviews)
  POST   /api/candidates/<id>/resume       upload resume file

INTERVIEWS
  GET    /api/interviews                   list (?candidate_id=, ?job_id=, ?upcoming=)
  POST   /api/interviews                   schedule (auto-moves candidate to interview)
  GET    /api/interviews/<id>              detail
  PUT    /api/interviews/<id>              update (incl. assessment_form)
  DELETE /api/interviews/<id>              delete

EMPLOYEES
  GET    /api/employees                    list (with paystub_count, document_count)
  POST   /api/employees                    create
  GET    /api/employees/<id>               detail (with paystubs + documents arrays)
  PUT    /api/employees/<id>               update
  DELETE /api/employees/<id>               delete
  POST   /api/employees/<id>/paystub       upload paystub PDF
  POST   /api/employees/<id>/document      upload document
  GET    /api/employees/<id>/files/<path>  serve paystub/document file

RESUMES
  POST   /api/resume/parse                 upload + parse resume (returns structured data)
  POST   /api/resume/parse/<candidate_id>  parse + attach to candidate

MISC
  GET    /api/scorecard-criteria           default criteria list
  GET    /uploads/<filename>               serve uploaded resume files
  GET    /                                main page

5. DATA MODEL (JSON schemas)
================================================================================

JOB (data/jobs/<id>/job.json)
  id, title, department, location, status (active/filled/closed),
  employment_type, description, requirements, scorecard_criteria[],
  created_at, updated_at

CANDIDATE (data/candidates/<id>/candidate.json)
  id, name, email, phone, job_id, stage (applied/screening/interview/
  offer/hired/rejected), applied_date, source, notes, resume_filename,
  parsed_skills[], parsed_education[], parsed_experience,
  created_at, updated_at

INTERVIEW (data/interviews/<id>/interview.json)
  id, candidate_id, job_id, interviewer, scheduled_date, scheduled_time,
  type (phone/video/in-person/practical), status (scheduled/completed/
  cancelled), location_or_link, ratings{}, notes, recommendation,
  assessment_form (full SLF form object), created_at, updated_at

EMPLOYEE (data/employees/<id>/employee.json)
  id, name, email, phone, position, location, status (active/inactive/
  terminated), start_date, sin, wage, emergency_contact, notes,
  certifications{}, address, birthday, uniform{}, vacation_pay,
  termination_date, termination_reason, documents[],
  created_at, updated_at
  PLUS folders: paystubs/*.pdf, documents/*

ASSESSMENT_FORM structure (stored on interview):
  position_applied, status_in_canada, arrival_date, semester, residence_city,
  drivers_license, drivers_license_class, commute_type,
  canadian_work_experience, english_proficiency, conflict_resolution,
  food_experience, smart_serve, previous_employer, previous_position,
  reason_for_leaving, references,
  requirements { sweeping, toilet, dishes, lift50, rawmeat, uniform, nails,
                 allergies, food_handler, seven_shifts, yoobic, ameego,
                 unpaid_training, three_day_training, open_close, probationary },
  logistics { hours_per_week, wage_expectation, earliest_start_date,
              reliable_commute, additional_commitments },
  availability { monday..sunday x {morning, afternoon, evening} },
  assessment { impressions, strengths, concerns, overall_rating,
               recommended_wage, decision, next_steps,
               interviewer_name, date }

8. KNOWN NOTES / PITFALLS
================================================================================

  - Flask dev server (python app.py) is fine for internal use; for
    production use gunicorn (see Dockerfile).
  - Never put the Cloudflare API token or passwords in committed files —
    GitHub secret scanning will block pushes (use env vars).
  - The trycloudflare.com quick-tunnel URL changes on every restart;
    the named tunnel + DNS CNAME gives a permanent URL.
  - data/ and uploads/ are gitignored — they hold real employee data.
  - import_employees.py re-runs are safe (idempotent by employee name).
  - When adding fields to the assessment form, update BOTH the render
    function (openScorecard) AND the collector (_collectAssessmentForm).
